# AGENTS.md

## Work In This Repo
- Use `task` from the repo root for Docker-backed operations; run `task --list` before guessing task names.
- `AGENTS.md` is a symlink; preserve the link and edit its target if updating these instructions.
- Main PR target is `develop`; GitHub Actions usually trigger CircleCI, whose dynamic config is generated by `.circleci/generate_config.sh`.

## Code Boundaries
- `tdrs-backend/`: Django 5/DRF API with Pipenv Python 3.10.8. App code is `tdpservice/`; URL wiring is `tdpservice/urls.py`; local settings are `tdpservice.settings.local`.
- Backend routes are mostly under `/v1/`; Keycloak auth routes also exist under `/v2/` and versionless canary routes.
- Data-file S3 access is centralized in `tdpservice/data_files/s3_client.py`; local `USE_LOCALSTACK=yes` maps it to LocalStack.
- `tdrs-frontend/`: CRA React 18 app with Redux, React Router v6, and USWDS. Entry is `src/index.js`; routes are in `src/components/Routes/Routes.js`.
- Frontend uses Yarn 4.6.0 via Corepack and `.yarnrc.yml` sets `nodeLinker: node-modules`; browser env vars must be `REACT_APP_*`.
- `tdrs-services/parser/`: Go parser (`go 1.25.5`) with `cmd/parser` and `cmd/docgen`; runtime config is YAML under `config/`.
- Parser logic exists in both `tdrs-backend/tdpservice/parsers/` and `tdrs-services/parser/`; inspect the call path or issue scope before changing only one.
- SQLC generated files live in `tdrs-services/parser/internal/db/`; do not edit generated Go by hand.

## Local Services
- Copy `tdrs-backend/.env.example` to `tdrs-backend/.env` before backend work; do not commit real secrets.
- `task backend-up` starts the backend stack on `http://localhost:8989` and creates the external Docker network `external-net`.
- `task frontend-up` starts the nginx frontend image on `http://localhost:3000`.
- For frontend localdev/hot reload, use `task frontend-update` or `docker compose -f tdrs-frontend/docker-compose.local.yml up -d --build tdp-frontend`.
- `task up` and `task down` start and stop the backend plus nginx frontend stacks.
- If GHCR image pulls fail from a fork, set `REGISTRY_OWNER` in local env as documented in `tdrs-backend/.env.example`.

## Backend Commands
- Setup/update: `task init-backend`, `task backend-update`, `task backend-makemigrations`, `task backend-migrate`.
- Django commands: `task backend-exec CMD="showmigrations"`; shells: `task backend-shell`, `task backend-bash`.
- Focused pytest: `/test backend tdpservice/reports/test/` or `task backend-pytest PYTEST_ARGS="tdpservice/reports/test/test_models.py::TestClass::test_method -v"`.
- Lint: `/lint backend` or `task backend-lint`.
- Backend formatting config is split: Black/isort line length 88 in `pyproject.toml`/`setup.cfg`, Flake8 max 120, migrations excluded.

## Frontend Commands
- Install/update deps: `task frontend-install` for host install, or `task frontend-init` / `task frontend-update` for Docker localdev.
- Focused Jest: `/test frontend FeedbackReports` or `task frontend-test JEST_ARGS="--testPathPattern=FeedbackReports"`.
- Taskfile appends `--watchAll=false` for Docker Jest; if bypassing Taskfile with `yarn test`, set `CI=1` or pass `--watchAll=false`.
- Coverage: `task frontend-test-cov JEST_ARGS="--testPathPattern=FeedbackReports"`.
- Lint: `/lint frontend` or `task frontend-lint`.
- E2E: prefer `task frontend-e2e-ci-local`; if invoking Cypress manually, run `task e2e-env-var-setup` first and set `CYPRESS_TOKEN=local-cypress-token`.

## Go Parser Commands
- Install local prerequisites when needed: `go install gotest.tools/gotestsum@latest` and `go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.30.0`.
- Focused test from `tdrs-services/parser/`: `gotestsum -- -count=1 -run TestName ./internal/parser/...`.
- Mirror CI parser verification with `task parser:compile-check`, `task parser:lint`, `task dump-parser-schema`, `task parser:sqlc-diff`, `task parser:sqlc-vet`, `task parser:validate-config`, and `task parser:test-all-coverage`.
- Do not substitute `task parser:ci-checks` or `task parser:sqlc-verify` in this checkout; `Makefile` currently has no `sqlc-verify` target.
- If Django model/table changes affect parser storage, run `task dump-parser-schema`, then from `tdrs-services/parser/` run `sqlc generate` and verify with `task parser:sqlc-diff`.

## Testing Expectations
- After backend/frontend/e2e code changes, run the narrowest relevant `/test` skill target; for Go parser changes, use the parser commands above.
- If tests fail, prefer fixing incorrect tests first; change source only when the failure output and surrounding code show an implementation defect.
- Backend test tasks bring up Docker services automatically. Go parser integration tests require backend Postgres/migrations and `DATABASE_URL=postgres://tdpuser:something_secure@localhost:5432/tdrs_test?sslmode=disable`.

## CI And Deploy
- PR checks are GitHub-triggered CircleCI jobs; generated CircleCI config combines `.circleci/base_config.yml` with the `build-and-test`, `deployment`, `owasp`, and `util` YAML fragments.
- Deploy mapping: `develop` -> `tdp-backend-develop`/`tdp-frontend-develop` in `tanf-staging`; `main` -> staging; `master` -> production.
- PR label `Deploy with CircleCI-<env>` triggers a dev deployment after successful status checks.
- Do not manually deploy or change Cloud.gov/Terraform state unless the user explicitly asks.
